# Frontend: SignLearn AI

ปรับหน้าเว็บตามตัวอย่างที่ตกลงกัน โดยไม่แก้ `server.py`, `engine.py`, วิดีโอ หรือข้อมูลท่าต้นแบบ

## โครงสร้างไฟล์ใหม่

| ไฟล์ | หน้าที่ |
| --- | --- |
| `index.html` | โครง HTML, โหลดฟอนต์/CSS/JavaScript, header และ Contact |
| `styles.css` | สี ฟอนต์ การจัดวางทุกหน้า responsive และโมชั่น แบ่งเป็น 9 หัวข้อ |
| `app.js` | สร้างหน้าจอใน `views`, โหลดบทเรียนจาก API, เปิดกล้อง และรับส่ง WebSocket |

หน้าจอย่อยยังสร้างด้วย JavaScript ภายใน `views` ตามรูปแบบเดิม ไม่ได้แยกเป็น HTML หลายหน้า

## การทำงานที่รักษาไว้

- API เดิม: `/api/chapters`, `/api/words/{chapter}`, `/api/video/{chapter}/{word}`
- WebSocket เดิม: `/ws/session`
- คำสั่งเดิม: `config`, `start`, `stop`, `evaluate`
- threshold เดิม: `0.14`
- ส่งภาพ JPEG กว้าง 640px คุณภาพ 0.85 โดยไม่ flip ก่อนส่ง ส่วน backend ยังเป็นผู้ flip ภาพ
- การประเมินและข้อมูลต้นแบบยังเป็นหน้าที่ backend เดิม ไม่มีคะแนนหรือคำศัพท์จำลองใน frontend
- เก็บการแสดงภาพข้อผิดพลาด สรุปนิ้วที่ควรฝึก รายละเอียดข้อต่อ และการฝึกซ้ำ

## เพิ่มการจัดการสถานะใน frontend

- ไม่ให้ผล API ที่กลับมาช้าเขียนทับหน้าหรือหมวดใหม่
- ล้างคำศัพท์ที่เลือกเมื่อเปลี่ยนหมวด
- ปิดกล้องและ WebSocket เมื่อออกจากหน้าหรือปิดหน้าเว็บ
- หากอนุญาตกล้องช้าหลังจากออกจากหน้าแล้ว จะหยุด stream ที่เพิ่งได้รับทันที
- รองรับการปฏิเสธกล้อง การเชื่อมต่อหลุด และการรอข้อมูลมือครั้งแรกเกิน 15 วินาที
- ข้อความประเมินผิดพลาดยังคงอยู่จนกว่าจะเริ่มฝึกใหม่ ไม่ถูกข้อความสถานะมือเขียนทับ
- กรณีวิดีโอหายจะแสดงปุ่มลองใหม่ และไม่ให้เริ่มบันทึก

## หากต้องการแต่งต่อ

1. เปลี่ยนสีที่ `:root` ใน `styles.css`
2. เปลี่ยน header และข้อมูล Contact ใน `index.html` (ข้อมูลติดต่อปัจจุบันเป็น placeholder)
3. เปลี่ยนข้อความ/โครงหน้าใน `views.home`, `views.words`, `views.hand`, `views.practice`, `views.result` ของ `app.js`
4. เปลี่ยนคำอธิบายหมวดที่ `chapterDesign` ใน `app.js`
5. ปรับโมชั่นที่หัวข้อ 8 และ breakpoint ที่หัวข้อ 9 ใน `styles.css`

ชื่อคำศัพท์ยังใช้ `label` จาก backend เดิม จึงอาจมีทั้งภาษาไทยและอังกฤษตามข้อมูลที่ได้รับ

## การเปิดใช้งานและผลตรวจ

เปิดผ่าน backend เดิมของโปรเจกต์ซึ่งเสิร์ฟ `frontend/` อยู่แล้ว ไม่ต้องใช้ npm หรือ build
การเปิด `index.html` โดยตรงหรือใช้ static server อย่างเดียวจะไม่ทำให้ API/กล้องประเมินทำงานครบ
งานนี้ไม่ได้ติดตั้งหรือแก้ Python environment และไม่ได้อัปเดตเว็บตัวอย่างบน Sites

ตรวจ syntax ของ JavaScript และทดสอบผ่าน Chromium โดยใช้ API/กล้องจำลอง:
- หน้าแรกและการ์ด 4 ขั้นตอน
- sidebar และการเปลี่ยนคำศัพท์ พร้อม API error/retry และผลตอบกลับผิดลำดับ
- ปฏิเสธกล้อง การรอความพร้อม และคำสั่งเริ่มบันทึก/ประเมิน
- ข้อความผิดพลาด การแสดงผลคะแนน/ภาพและลำดับข้อผิดพลาด
- หยุด stream เมื่อออกจากหน้า รวมกรณีอนุญาตกล้องล่าช้า
- reduced motion และไม่มี horizontal overflow ในหน้าหลัก/บทเรียนที่ 1440, 1024, 768, 375, 320px

ยังไม่ได้ยืนยันการตรวจจับมือและคะแนนกับกล้องจริง/เซิร์ฟเวอร์ Python จริง
